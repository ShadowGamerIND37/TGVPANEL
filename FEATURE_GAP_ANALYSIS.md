# TGVPANEL Feature Gap Analysis

**Audit baseline:** active branch `arena/1339f942-tgvpanel`, based on `97e5d76c41f10ebbd0066230fb4917d14e27c6df` (`main`, the merge of PR #40). This audit was performed against the **complete Virtualizor-level upgrade roadmap** (sections A–R: advanced virtualization, storage, networking/VPC, firewall/security, backup/DR, snapshots/migration, cluster/HA, templates/ISO, Docker, load balancer, billing, admin/customer API, DNS, monitoring, white-label/UI, import tools, hardening/scalability, install/update/recovery). This is an existing Node.js/TypeScript + Express + EJS + SQLite product; recommendations extend its modules and do not propose a rebuild or replacement control panel. Findings were checked against `src/`, `app.js`, EJS pages, migrations, scripts, tests, README, and `docs/PHASE1_SOURCE_AUDIT.md`; that legacy source map contains historical/stale claims and is not current test evidence. This is an **audit-only** pass: no production functionality was modified during this audit.

## Requested roadmap checklist (individual capability status)

`FULLY IMPLEMENTED` at roadmap-system scope is reserved for the existing reseller subsystem, per owner direction. Other areas may have tested slices but remain PARTIALLY IMPLEMENTED at phase scope. Phase 0 reproduced misleading KVM telemetry: hardcoded zero RX/TX and a loopback IP sentinel. Phase 1 corrected those fields to null when unmeasured; KVM network traffic remains unavailable rather than claimed as implemented. `NEEDS SECURITY IMPROVEMENT` identifies deployment/control gaps without claiming an exploit was reproduced. The existing generic bearer PAT remains compatible for its existing use and is not a substitute for reseller HMAC credentials.

## Audit conventions and verification

`FULLY IMPLEMENTED` at roadmap-system scope is reserved for the reseller system explicitly identified as complete by the owner. Other areas may have implemented and tested slices but remain PARTIALLY IMPLEMENTED at phase scope. The Phase 0 `BROKEN` KVM telemetry findings (constant zero RX/TX and missing-IP loopback sentinel) were corrected in Phase 1: current adapter output is null where data is unavailable, without implying KVM network measurement support. `NEEDS SECURITY IMPROVEMENT` identifies control gaps without claiming an exploit was reproduced. The supplied 20-phase roadmap is the capability comparison baseline available in this workspace; no independent Virtualizor product documentation was supplied for a separate vendor-by-vendor benchmark. `tests/run-all.js` is broad regression evidence, but some host-specific cases install test command harnesses/stubs when hypervisor binaries are absent (notably T13/T24); passing those cases does not establish live production KVM/Proxmox compatibility or real-cluster performance.
