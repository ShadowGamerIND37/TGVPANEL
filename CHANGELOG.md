# Changelog

## Unreleased — Phase 2 started (2026-10-30)

- Phase 2 scope is TGVPANEL's own KVM/LXC control plane: improve host capability accuracy, safe lifecycle/error behavior, and KVM/LXC integration validation within the existing architecture.
- Per owner direction, do not integrate Proxmox/vendor APIs, external hypervisor API keys, or vendor credential workflows. Existing Proxmox OS templates are just install media/templates and do not change this scope.
- Hardened the native KVM adapter restart contract: when no dedicated restart hook exists, restart now requires both stop and start hooks and rejects instead of returning apparent success without performing an operation. Added acceptance coverage for rejection and ordered stop/start fallback.
- Improved native host probing for ARM-only systems: QEMU version detection now selects `qemu-system-aarch64` when x86_64 QEMU is absent, while preferring x86_64 when both are installed. T08 covers ARM-only, both-present, and neither-present selection. This reports installed QEMU accurately; it does not claim every TGVPANEL guest template supports ARM.
- Hardened native LXC lifecycle state integrity: a failed host stop now prevents persistence of administrative suspension, and a failed host destroy no longer silently deletes panel records. T08 covers both host-failure contracts.
- Hardened native KVM lifecycle state integrity: fallback stop now waits for the guest process to exit before recording stopped; suspension stops a live guest process even when the recorded status is stale before recording suspension; deletion refuses without a registered host delete hook instead of removing panel records while leaving guest artifacts on the host; stale “running” state with no stop hook or live PID is rejected instead of being marked stopped/suspended; and hook-backed start, stop, restart, and suspend now verify the persisted guest process state before recording the panel status. T08 covers all fallback guards and hook-state failures.
- Improved native host capability accuracy: QEMU system binary selection now prefers the installed binary matching the detected host CPU architecture, reports whether that binary matches the host architecture, and health warnings disclose a QEMU architecture mismatch. T08 covers ARM/x86 selection and mismatch checks. This reports installed host tooling; it does not validate guest-template compatibility.
- Hardened native KVM deletion integrity: fallback deletion without a registered `deleteVmById` host hook now refuses instead of deleting panel records while leaving guest disk artifacts on the host, and hook-backed deletion now verifies the VM row is gone and no live guest process remains before reporting success. T08 covers both refusals.
- Hardened native LXC lifecycle state integrity: start, restart, freeze, unfreeze, stop, and suspension now verify the host-reported container state before persisting panel status, so the panel does not record running/frozen/stopped unless the host inspection confirms it. Deletion now inspects the host container first and only requires destroy verification when the container exists; panel records are removed for missing/meta-only containers without host destroy tooling, and never removed when a destroy leaves the container behind. T08 covers both host-state mismatch refusals and the missing-container delete path. Phase 2 and Phase 1 remain in progress.

## Unreleased — Phase 1 in progress (2026-10-30)

- Added backed-up migration v020 and tracked v1 APIs for KVM secondary-disk and NAT-NIC workflows. These configuration changes require a stopped VM; disk detach preserves/catalogs image data and supports reattach. Bridge networks and live QEMU hotplug are not exposed.
- Added backed-up migration v021 for local VNC configuration, loopback-only QEMU VNC startup, an authenticated per-VM WebSocket-to-TCP bridge with same-origin browser checks, and vendored noVNC 1.7.0 assets with license. VNC settings require a stopped VM and take effect on next start.
- Added a restricted stopped-NAT KVM clone workflow with flattened, verified primary-disk copy, new MAC/SSH-forward port, and explicit acknowledgement that guest machine-id, SSH host keys, and secrets remain copied. Clone disk output and warnings are visible in the admin unified page.
- Added an LXC clone workflow through the host allowlisted `lxc-copy` utility for stopped, directory-backed containers. The clone remains stopped with host networking detached to prevent immediate duplicate-IP/MAC conflicts; guest identity, secrets, and in-guest static network configuration remain duplicated and must be reviewed. User/admin controls require acknowledgement; real host `lxc-copy` interoperability is not yet validated.
- Added guided KVM rescue-ISO configuration for stopped VMs: select a managed operator-supplied ISO for the next boot, then detach it later to restore disk-first boot. This does not provide rescue media, verify bootability, or automate guest repair/password reset.
- Added backed-up migration v022 and staff-only per-instance service lock state for KVM/LXC. The lock does not suspend/stop a running guest, but blocks start and restart until explicitly cleared; admin UI controls and acceptance coverage were added.
- Added additive SQLite migration v019 for persistent VPS lifecycle task history and a partial unique index preventing more than one queued/running unified lifecycle operation per engine/instance.
- Added asynchronous lifecycle execution opt-in on the existing unified instance action endpoint (`async: true`) while preserving the default synchronous response contract; unified v1 synchronous actions and bulk operations also record history and share the per-instance lock.
- Added owner/staff-authorized task status and per-instance history endpoints. Added task progress/history UI to the existing admin and customer unified instance pages; opaque hypervisor operations remain indeterminate rather than showing fabricated percentage progress.
- On startup, every unfinished queued/running task left by the previous controller process is marked interrupted/failed for operator verification; dangerous operations are not retried automatically.
- Added shared task locking/history middleware to legacy KVM lifecycle/delete and selected mutation routes (start/stop/restart/delete, configuration edit, reinstall, ISO attach/detach, snapshot create and guest serial-console commands) without changing their synchronous HTTP response contracts.
- Added per-instance task locking/history around every current direct `/api/v1/lxc/:id` mutation: resize/configuration, reinstall, network repair, root-password reset, SSH-key injection, tunnel start, renewal/ownership/sharing, and file write/delete. Task rows persist only a completion marker, not adapter responses that could contain credentials or host details.
- Reconciled the admin license-page copy with implemented browser VNC/noVNC and SSH/serial console paths.
- Corrected KVM telemetry honesty: unavailable RX/TX counters and missing guest IPs now return null instead of fabricated zero traffic or the loopback address; no KVM network measurement is claimed.
- Implemented safe KVM virtual-disk expansion through the existing edit workflow and unified v1 API. It requires a stopped VM and a managed standalone QCOW2/raw image, rejects shrink/backing-chain/out-of-directory disks, persists task history, and clearly leaves guest filesystem growth to the guest OS.
- Preserved reseller routes, authentication/key schema, and HTTP request/response contracts. Reseller VPS lifecycle calls now share the manager's per-instance task lock/history while remaining synchronous; reseller key, CRM, and account management endpoints remain untouched.
- Phase 1 remains incomplete: LXC clones on non-directory backends, a bundled rescue image or automated guest recovery, live device hotplug/bridged NIC workflows, broad legacy-route locking, adapter-reported progress and consistent rollback remain outstanding. VNC is implemented but needs real-QEMU integration validation.
